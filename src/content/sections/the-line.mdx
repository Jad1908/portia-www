title: "The agent may author a transform. It may never author a number."

**Deterministic code owns facts and consequences.** Every drop count, null rate,
key overlap and row conservation comes from a reproducible function the copilot
calls. It has no filesystem tools and no shell, so it cannot go and read your
data — its whole view is the evidence a check handed back.

**The copilot owns judgment.** Which facts are material given a goal the engine
has no way to know, what to ask, how to frame it, what to recommend. The checks
layer is forbidden from ranking, scoring or prioritizing on its behalf, because
that bakes context-free judgment into code that then fails on exactly the subtle
problems it was added for.

**It can still write a transform.** Where the prewritten operations cannot
express something, the copilot authors one DuckDB `SELECT` — captured verbatim
in the spec, executed by the engine, and measured by the same harness as every
other step. A decision you read in a diff, not a reasoning act that happened
somewhere you cannot see.

**And a zero is refused, not warned about.** An empty table, a column that went
in with data and came out all null, a source that contributed nothing, a claim
about grain that turns out not to be unique: the step is not written. The
blocking set holds zeros only, on purpose — a zero needs no threshold to be a
fact, and the moment a tunable number joins it, code is deciding what counts as
bad.
