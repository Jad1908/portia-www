**This part is not built, and it is not scheduled.** It is a UI vision before it
is a mechanism, and saying so is cheaper than being caught. What makes it worth
stating anyway is the constraint it starts from, because that constraint is the
whole design:

**The data is never pulled down.** Warehouse tables are too large to work with
locally, and copying them would reintroduce the hidden second copy portia
already spent a release deleting. Measurements are queries that run where the
data is; only small results come back. Everything portia writes — the catalog
entries, the specs, the compiled `.sql` — still lands in your repo, exactly as
it does now.

Collaboration is the same shape of *not yet*. portia is project-local today:
no central store, nothing that aggregates across projects, no shared history. A
shared catalog is where the durable decisions stop being one person's and start
being the team's — which was the argument for keeping them as plain files in the
first place.
